     LightRAG 版本升级评估与方案

     Context

     用户询问是否需要升级 LightRAG 到 2026 年 5 月新版本（当前 1.4.14 → 最新
     1.5.4）。新版本引入三个特性：
     1. RagAnything 并入 LightRAG（MinerU / Docling 多模态解析）
     2. 四种切块策略（Fix / Recursive / Vector / Paragraph）
     3. 分角色 LLM 配置（EXTRACT / KEYWORDS / QUERY / VLM）

     当前架构关键事实：
     - LightRAG 版本：lightrag-hku==1.4.14（未锁版本，requirements.txt 写
     lightrag-hku）
     - 切块在 LightRAG 外部完成：ingestion.py:242-246 使用
     LlamaIndex.SentenceSplitter，切好的文本直接 rag.ainsert(batch) 进入
     LightRAG
     - 图片处理在 LightRAG 外部完成：image_extractor.py 调用 VLM 提取图片描述 →
     ainsert，且有 LlamaParse 兜底扫描件 PDF
     - LLM 配置：lightrag_engine.py:268-274 所有角色共用一个 _llm_model_func（走
     TEXT_MODEL，如 qwen-max）
     - ingestion.py:407 已预留 RagAnything 接口但作为可选依赖（except 
     ImportError 跳过）

     ---
     逐特性分析

     特性 1：RagAnything 并入（MinerU / Docling 多模态解析）

     ┌────────────┬────────────────────────────────────────────────────────────┐
     │    维度    │                            分析                            │
     ├────────────┼────────────────────────────────────────────────────────────┤
     │ MinerU     │ 中文学术 PDF 布局识别远超 PyMuPDF，对复杂表格/公式更好     │
     │ 优势       │                                                            │
     ├────────────┼────────────────────────────────────────────────────────────┤
     │ 你的现状   │ 已有 LlamaParse 云端解析兜底扫描件 PDF；image_extractor.py │
     │            │  VLM 提取图片                                              │
     ├────────────┼────────────────────────────────────────────────────────────┤
     │ 依赖代价   │ MinerU 安装需要 torch + paddleocr，镜像膨胀 1-2 GB         │
     ├────────────┼────────────────────────────────────────────────────────────┤
     │ 架构冲突   │ 你的切块在 LightRAG 外做，新版想在 LightRAG                │
     │            │ 内做，两套并行会混乱                                       │
     ├────────────┼────────────────────────────────────────────────────────────┤
     │ API 变化   │ raganything API 已并入，需重写 ingestion.py:407 的         │
     │            │ ImportError 分支                                           │
     └────────────┴────────────────────────────────────────────────────────────┘

     结论：❌ 不建议升级

     你有成熟的 LlamaIndex 解析层（PPTX/DOCX/图像 PDF），比 LightRAG
     内置更完整。MinerU 的中文学术 PDF 优势被 LlamaParse
     兜底覆盖，依赖膨胀得不偿失。

     ---
     特性 2：四种切块策略（Fix / Recursive / Vector / Paragraph）

     ┌──────────────┬──────────────────────────────────────────────────────────┐
     │     维度     │                           分析                           │
     ├──────────────┼──────────────────────────────────────────────────────────┤
     │ 你的现状     │ ingestion.py:242-246 在 LightRAG 外部用 SentenceSplitter │
     │              │  切块，切好的文本直接 ainsert                            │
     ├──────────────┼──────────────────────────────────────────────────────────┤
     │ LightRAG     │ 只在调用 ainsert_files(all_files) 原生摄入时生效         │
     │ 内部切块     │                                                          │
     ├──────────────┼──────────────────────────────────────────────────────────┤
     │ 冲突         │ 你走的是 ainsert(chunks) 外部切块路径，LightRAG          │
     │              │ 内部切块策略完全不生效                                   │
     └──────────────┴──────────────────────────────────────────────────────────┘

     结论：❌ 升级对你没用（除非重构架构）

     要享受切块策略必须改成 ainsert_files 走 LightRAG 原生摄入，但这意味着放弃
     LlamaIndex 的文档解析层（它处理 PPTX/DOCX/图像 PDF 比 LightRAG
     内置更完整）。

     例外：若未来仅处理纯文本 PDF，可改用 LightRAG 原生摄入 +
     四种策略。但目前教育类课程资料 PPTX/DOCX/扫描件居多，LlamaIndex
     解析层不可弃。

     ---
     特性 3：分角色 LLM 配置（EXTRACT / KEYWORDS / QUERY / VLM）

     ┌───────────────────────────┬────────────────────┬────────────────────────┐
     │           角色            │        当前        │       升级后可用       │
     ├───────────────────────────┼────────────────────┼────────────────────────┤
     │                           │ TEXT_MODEL（如     │ qwen-turbo /           │
     │ EXTRACT（索引时实体提取） │ qwen-max，贵）     │ qwen-plus（便宜        │
     │                           │                    │ 5-10x）                │
     ├───────────────────────────┼────────────────────┼────────────────────────┤
     │ KEYWORDS（关键词提取）    │ TEXT_MODEL         │ 最快最便宜的模型       │
     ├───────────────────────────┼────────────────────┼────────────────────────┤
     │ QUERY（用户问答）         │ TEXT_MODEL         │ 保持                   │
     │                           │                    │ qwen-max，维持质量     │
     ├───────────────────────────┼────────────────────┼────────────────────────┤
     │ VLM（图片理解）           │ 自己调用 VLM       │ 可统一进 LightRAG 管理 │
     └───────────────────────────┴────────────────────┴────────────────────────┘

     收益分析：
     - 索引时 EXTRACT 是 token 大头（一次摄入几百个 chunk，每个 chunk
     都要提取三元组）
     - 切换成 qwen-turbo（~0.3 元/百万 token）vs qwen-max（~2 元/百万
     token），索引成本降 70-80%
     - 教育类课程 KB 累计摄入量大，成本节省显著

     结论：✅ 唯一值得升级的特性
